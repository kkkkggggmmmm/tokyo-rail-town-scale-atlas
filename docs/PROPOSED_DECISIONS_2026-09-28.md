## 提案1　京浜東北・根岸線と総武線各駅停車の駅の抜けを直す

**何が起きているか**

固定した駅の並び（exact segment）から、6駅が抜けているとみられます。

- 京浜東北・根岸線は42駅で固定されています。次の5駅がありません。
  - さいたま新都心—浦和の間：与野・北浦和
  - 田端—上野の間：西日暮里・日暮里・鶯谷
- 総武線各駅停車は21駅で固定されています。新小岩—市川の間の小岩がありません。
- 公開サイトの路線表示でも、田端の次がいきなり上野になっています。

**正しい駅数について（推定です）**

- 国土数値情報（N02）の駅データと、JRの駅番号（JK01〜JK47、JB18〜JB39）からは、正しくは47駅・22駅と推定されます。
- ただし、この環境からは鉄道会社のサイトに接続できませんでした。公式の駅一覧による一次確認はまだです。

**推奨**

次の変更を一つの決定として記録します。

- DEC-0012 の2路線の駅数を改める。
- DEC-0018 の「既存8路線の並びは凍結」を、この2路線に限って解除する。
- 駅の並びの指紋（station_order_sha256）を固定し直すことを認める。
- 判定記録（PHASE1_G2_ADJUDICATIONS）を更新する。

6駅には、首都圏全駅の拡張（DEC-0018）で振ったID（opaque ID：意味を持たない番号）をそのまま使います。新しい番号は振りません。

**反映の手順**

採用後、次の順に進めます。いずれも生データ（raw data）を持つ実行環境で行います。

1. 鉄道会社の公式駅一覧を確認し、URLと確認日を記録する。
2. 6駅のIDを G2 の番号帳（`PHASE1_IDENTITY_REGISTRY.yml`）に先に登録する。登録しないと、作り直しのときに別の番号が振られてしまう。
3. G2 → G3 → 公開データを1回でまとめて作り直す。
4. `verify-locked` と `verify-g3` の検査を通す。

**準備済みのもの**

- 抜けの記録：`data/reference/G2_CORRIDOR_CORRECTION_2026-09-28.yml`
- 抜けを自動で見つける検査：`scripts/validate_corridor_completeness.py`（`make verify-fast` に組み込み済み）

**検査の限界**

- 首都圏の閲覧範囲（DEC-0018）の外にある区間は、比べる材料がリポジトリに無いため検査できません。
  - 小田急線：東海大学前—小田原
  - 東上線：北坂戸—寄居
  - つくばエクスプレス：流山おおたかの森—つくば
- 隣り合う駅が複数まとめて抜けた場合は、一部しか検出できないことがあります。

## 提案2　N03を使わずに解析範囲を決めるルール

**背景**

OWNER-2026-09-06-N03 は、「実データでの抽出の前に、N03を使わない範囲決定の契約（contract）を整える」ことを求めています。

**推奨**

`data/reference/N03_FREE_SCOPE_CONTRACT.yml` の案を採用します。

- e-Statのメッシュデータに付いている都道府県コードと、メッシュ番号から計算できる格子の形だけで範囲を決めます。
- 境界の図形（polygon）は一切使いません。

**採用に必要なこと**

DEC-0014 は、県境をまたぐメッシュを合算する前に「行政界による範囲の切り出し（clip）」を求めています。この案はその代わりになるため、DEC-0014 を改める決定が必要です。

**守ること**

- 県境をまたぐメッシュの数値を、面積で按分しない。
- 行が無いメッシュを、ゼロで埋めない。
- つくばエクスプレス沿線（茨城県側）は、N02の線路形状から5km以内のメッシュに限る。

**実行の条件**

1. Ownerが採用し、DEC-0014 を改める。
2. 実データ（G3の派生データ）での検査が通る。
3. 感度分析（sensitivity analysis）で、範囲を9.5・10・10.5kmと変えても表示範囲の結果が変わらないことを確かめる。
4. 結果は Git に入れない場所（`data/derived/`、`data/qa/`）にだけ置き、範囲の図形はコミットしない。

**既知の限界**

長野県（20）は埼玉県と接していますが、取得済みの県に入っていません。埼玉—長野の県境のメッシュは「成分がそろっていない」扱いになります。

**公開**

この案だけでは、集計結果の公開は許可されません。

**推奨**

- 正解は手描きの図形ではなく、500mメッシュごとの「中心・周辺・外」のラベルで記録する。

## 提案6　データの意味づけの食い違いを直す

| 論点 | 推奨 |
|---|---|
| `imputed`（補完値）が空欄でもよいか | 空欄は不可。補完できなかった行は、元の欠損状態のままにする |
| `invalid`（不正な値）の行を保存してよいか | 保存しない。検査用の隔離出力にだけ出す |
| 地価（L01）の指標名 | 全地点を `land_price_standard_point`、商業地だけを `commercial_land_price` に分ける |
| G3の `food_*` 指標 | 中身は「宿泊業＋飲食サービス業」の合計なので `accommodation_food_*` に改名する。飲食店だけの指標は、公開サイトと同じ中分類76（T001163082）を使う |

`observed_zero`（観測ゼロ）の値が空欄の行を通してしまう問題は、辞書との食い違いではなく、単純な不具合です。そのため、この変更で修正済みです（`schema/canonical.sql`）。
