## 提案1　京浜東北・根岸線と総武線各駅停車の駅の抜けを直す

- **何が起きているか**：固定した駅の並び（exact segment）から6駅が抜けている。
  - 京浜東北・根岸線：与野・北浦和（さいたま新都心—浦和の間）、西日暮里・日暮里・鶯谷（田端—上野の間）。42駅で固定されているが、正しくは47駅。
  - 総武線各駅停車：小岩（新小岩—市川の間）。21駅で固定されているが、正しくは22駅。
  - 公開サイトの路線表示でも、田端の次がいきなり上野になっている。
- **推奨**：DEC-0012の駅数を47・22に改める。
  - 6駅には、首都圏全駅の拡張（DEC-0018）で振ったID（opaque ID：意味を持たない番号）をそのまま使い、新しい番号は振らない。
- **反映の手順**：生データ（raw data）を持つ実行環境で、G2 → G3 → 公開データを1回でまとめて作り直し、`verify-locked` と `verify-g3` の検査を通す。
- **準備済み**：
  - 抜けの記録：`data/reference/G2_CORRIDOR_CORRECTION_2026-09-28.yml`
  - 抜けを自動で見つける検査：`scripts/validate_corridor_completeness.py`（`make verify-fast` に組み込み済み）

## 提案2　N03を使わずに解析範囲を決めるルール

- **背景**：OWNER-2026-09-06-N03 は「実データでの抽出の前に、N03を使わない範囲決定の契約（contract）を整える」ことを求めている。
- **推奨**：`data/reference/N03_FREE_SCOPE_CONTRACT.yml` の案を採用する。
  - e-Statのメッシュデータに付いている都道府県コードと、メッシュ番号から計算できる格子の形だけで範囲を決める。
  - 境界の図形（polygon）は一切使わない。
- **守ること**：
  - 県境をまたぐメッシュの数値を面積で按分しない。
  - 行が無いメッシュをゼロで埋めない。
  - つくばエクスプレス沿線（茨城県側）は、N02の線路形状から5km以内のメッシュに限る。
- **実行の条件**：Ownerの承認に加え、次の2点がそろってから。
  - 実データでの検査が通ること
  - 感度分析（sensitivity analysis：範囲を9.5・10・10.5kmと変えても、表示範囲の結果が変わらないことの確認）
- **公開**：この案だけでは集計結果の公開は許可されない。

## 提案4　評価用の正解づくりのルール（Golden Eval）

- **推奨**：正解は手描きの図形ではなく、500mメッシュごとの「中心・周辺・外」のラベルで記録する。
- **使ってよい根拠**：現地の知識、公的な統計や計画、地理院タイルの閲覧（出典表示つき）、OSMの目視。
- **使ってはいけないもの**：Googleマップ・ストリートビュー・食べログからのトレースやデータの抜き出し。
- **順序**：検証用（holdout）の正解は、候補手法の結果を見る前に付ける。

## 提案6　データの意味づけの食い違いを直す

| 論点 | 推奨 |
|---|---|
| `imputed`（補完値）が空欄でもよいか | 空欄は不可。補完できなかった行は元の欠損状態のままにする |
| `invalid`（不正な値）の行を保存してよいか | 保存しない。検査用の隔離出力にだけ出す |
| 地価（L01）の指標名 | 全地点を `land_price_standard_point`、商業地だけを `commercial_land_price` に分ける |
| G3の `food_*` 指標 | 中身は「宿泊業＋飲食サービス業」の合計なので `accommodation_food_*` に改名する。飲食店だけの指標は、公開サイトと同じ中分類76（T001163082）を使う |

`observed_zero`（観測ゼロ）の値が空欄の行を通してしまう問題は、辞書との食い違いではなく単純な不具合です。そのため、この変更で修正済みです（`schema/canonical.sql`）。
